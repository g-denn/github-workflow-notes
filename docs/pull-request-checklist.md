# Pull request checklist

Use this short checklist before merging a change you own.

## Scope

- The pull request has one clear purpose.
- Its files belong to the intended repository and branch.
- Unrelated edits are left out of the diff.

## Evidence

- The description says what changed and why.
- The relevant checks ran, and their results are recorded.
- Any untested behavior or remaining risk is stated plainly.

## Merge

- Read the final diff after the last edit.
- Confirm the target branch and repository again.
- Merge only when the change meets that repository's review rules.
- Check the result after merging.
